# Changelog

`report.VERSION`, bumped in the same commit as any change to the pipeline's
numerics or output shapes (rule and rationale in `CLAUDE.md`'s Versioning
section). Newest first.

| version | what changed |
| --- | --- |
| 0.13.0 | **docking chooses what to refine by an energy window, not by rank.** `Docking` gains `refine_window_kcal` (3.0 kcal/mol, `--refine-window`) and `n_refine` changes meaning from "the number refined per parent" to a cost cap on it, default raised 10 -> 400 (`--refine` unchanged in name); `dock.json`'s params block gains the new field, which is why the version moves. Every screened basin within the window of *that parent's own* screened minimum is refined, best-first, up to the cap. **The screened ranking does not predict the refined one**, which is what the old flat top-10 assumed: refining all 410 screened basins of an acetone n = 1 grid run puts the best one **247th** by screened energy, 1.50 kcal/mol above the screened minimum, at -4.608 against top-10's -4.541 -- and raising the flat cap does not reach it (top-30 and top-50 both stall at -4.54), so 0.12.0's advice to "raise `--refine` before a `dft_export` from a grid run" was treating the symptom. Tightening the screen was measured and **rejected**: at `screen_fmax` 0.02 and 0.01 the winner still sits at rank 283 of 323 and 155 of 230, for 3.7x and 8.5x the screening cost and 1.6x/2.7x the total, so `screen_fmax` stays 0.05. **Not a grid-only change** -- 64 random placements yield 40-63 distinct screened basins per parent, not a handful, so the default mode was discarding four fifths of them too, and it gains the most: at the real defaults (`random`, `--parents 3`) chloroform goes -6.651 / -12.997 / **-18.167 -> -18.328** and acetone -4.563 / -9.366 / **-14.764 -> -15.653**, pools up 3-6x, for 2.3x and 3.8x wall-clock. Grid mode, one parent: acetone -15.123 -> **-15.678** and chloroform -18.208 -> **-18.384** at n = 3, pool 10 -> 324 and 8 -> 233. The cap is 400 and not 100 by measurement -- the two are indistinguishable at one fixed parent (-4.599 vs -4.608, under the dedupe tolerance) but over a chain cap 100 lands acetone n = 3 at -14.912, *worse* than the old top-10, since a cap small enough to bind is a rank cut again. For a fixed parent the refined set is now a strict superset of the old one, so `E_int(min)` can only fall or stay and a chain number moving the wrong way (acetone n = 2) is the known `n_parents` greediness. **A binding cap now says so**: each `parent_detail` entry gains `n_in_window` (how many basins the window admitted before the cap clipped it), the Per-parent detail table renames `placements` to `refined` and gains a `window` column beside it -- marked `!` when the two differ -- and `report.refine_cap_warning` prints a WARNING naming each capped parent, because a capped run has silently reverted to the rank cut the window replaced and nothing in its refined output would otherwise show it. Not additive on the reading side: a pre-0.13.0 `dock.json` has no `n_in_window` and now **raises** rather than re-rendering without the column, the same convention 0.7.0 and 0.11.0 set -- re-run the docking, do not re-report it. `n_refined` per run still reports the actual count. DESIGN.md gains "The screen-to-refine handoff: a window, not a rank" |
| 0.12.1 | grid mode's parent is **principal-axis aligned before placement**, as the random mode's always was, and the two modes now dispatch to one call each: `docking.random_placements` beside `grid_placements`, both going through the new `docking._pose_if_clear` so the tolerance test `grid_placements` documents as "the identical test `place_one` redraws on" is one function rather than two copies. **Grid-mode numbers move**, which is why the version does: the grid was *not* frame-independent, though `dock_at_n` said it was -- `_voxel_downsample` rounds against a lattice anchored at the lab origin and the orientations are lab-frame, so six rigid motions of bare pyrazine gave 3251-3564 poses against the file frame's 3355 (6.2%), at different places. Aligned, the pose set is bit-identical across rigid motions, up to `_principal_frame`'s eigenvector-sign ambiguity (3348-3363 poses, 0.4%), which is left alone because that same function sets the frame `pack_solvent` packs into. Measured, pyrazine/chloroform `--n 1 2 3 --parents 1 --place-mode grid`: **-6.6667 / -13.0222 / -18.2082** on 15,148 poses against 0.12.0's -6.6667 / -13.0025 / -18.3497 on 15,542 -- lower at n = 2, and the n = 3 rise is the greedy chain following that lower n = 2, the known `n_parents` caveat. **The random path is bit-for-bit unchanged** (verified: `dock.json` identical field for field at `--n 1 2 --parents 1 --placements 16`), and **no default moves**: `grid_probe_fracs` stays `(0.4, 0.7, 1.0)`, its six-line defence of the outer shell replaced by the measurement that shell is inert in chloroform *and* acetone -- kept because it is nearly free and because the concave solute that would justify it is untested. No field of `dock.json` or `scored.json` changes shape and an existing one re-renders unchanged (verified). DESIGN.md's "Systematic placement" closes its open question with the two shell tables, and gains the frame-dependence paragraph and the per-shell survival count a new solvent wants before these fractions are trusted |
| 0.12.0 | **systematic placement for `docking.py`**, beside the random draw. `Docking` gains `place_mode` (`"random"`, the unchanged default, or `"grid"`), `grid_spacing_A` (2.0 A), `n_orientations` (12) and `grid_probe_fracs` (`(0.4, 0.7, 1.0)`), with `--place-mode` / `--grid-spacing` / `--orientations` / `--grid-probe-fracs` behind them; `dock.json`'s params block gains all four, which is why the version moves. Grid mode enumerates positions x orientations instead of drawing `n_placements` poses: positions from the new `shell_capacity.surface_points` (`sasa` keeping its exposure mask's points instead of collapsing them to an area -- `sasa` itself is untouched, since it feeds the live `monolayer_capacity`), voxel-downsampled per shell by `docking._voxel_downsample`, one shell per `grid_probe_fracs` entry, crossed with `docking._orientation_quaternions` (super-Fibonacci over SO(3), Alexa 2022) and filtered by the same `tolerance` test `place_one` redraws on, so `n_placements_tried` is already post-rejection. **The grid is radial because a single surface measurably is not enough**: the solvent-centre surface is the contact distance for a sphere and 1.2-1.8 A too far out for a directional one (the both-N minimum puts a chloroform centroid 3.17 A from the nearest parent atom, that shell puts it at 4.37-4.92 A), and scanning it alone found the both-N basin in **0 of 2664** poses and reproduced the MD sweep's -11.44 kcal/mol at n = 2 rather than docking's -13.00. Measured on pyrazine/chloroform, `--n 1 2 3 --parents 1`, grid against random: `E_int(min)` **-6.6667 / -13.0025 / -18.3497** against -6.6514 / -12.9971 / -18.1672 -- lower at every n -- the both-N basin found by 6 of 10 refined placements against 2 of 10, `pool` 1/5/9 against 3/9/10 (narrower: a fixed `n_refine` of 10 taken off 5236 screened representatives instead of 64 concentrates on the best basins, so raise `--refine` before a `dft_export` from a grid run), 15,542 placements screened against 192, and 144 s against 13.2 s on 18 cores. `MAX_GRID_PLACEMENTS` (200,000 poses per parent) raises on a `grid_spacing_A` / `n_orientations` typo, and an unknown `place_mode` raises rather than falling through. **No default moves**: `place_mode` is `"random"` and `n_parents` stays 3 (measured: `--parents 3` buys 0.054 kcal/mol at n = 3 under grid mode, for 320 s against 144 s). Additive -- the random path is bit-for-bit identical to 0.11.0 on a fixed seed (verified, all three n), no field of `scored.json` moves, and an existing `dock.json` re-renders unchanged |
| 0.11.0 | the basin criterion becomes geometric. Two candidates are one minimum iff their energies agree within `report.DEDUPE_TOL_EV` (**5 meV**, widened from 1) *and* their contact descriptors within the new `report.GEOM_TOL_A` (**0.15 A**) -- both picked from measured gaps in a real pool, not guessed (DESIGN.md, "Geometric basin dedupe"). Every `scored.json` candidate gains a required `descriptor` field (`ensemble.contact_descriptor`: per-solvent-molecule closest distances to each solute atom, sorted within solute element blocks, plus the sorted solvent-solvent vdW gaps -- permutation- and rigid-motion-invariant, and deliberately not an RMSD, which would have been worse); `report` gains `descriptors_match`, `descriptor_distance`, `same_basin`, `MAX_DESCRIPTOR_MOLECULES`. `dedupe_groups` / `dedupe_energies` take the aligned descriptors as their new second argument, so **any caller passing `tol_eV` positionally must move it to a keyword**. `found_by`, the per-packing `best` marker and docking's per-parent `best` stop bypassing the criterion with an inline energy comparison and go through `same_basin`; `pooled[n]` gains `found_by_seeds` so `format_seed_detail` marks exactly the packings `found_by` counted. `Docking.screen_dedupe_tol_eV` 4 -> 10 meV with a new `screen_geom_tol_A` (0.5 A) beside it -- both stay deliberately looser than the scorer's, since a screened geometry is only relaxed to `screen_fmax`. Each summary and each params block records `dedupe_tol_eV` / `geom_tol_A`. **`E_int(min)` is invariant** -- it is a set minimum however the set is partitioned -- and unchanged at every n; what moves is `pool`, `found_by`, `n_seeds_hit`, every `basins` entry, `frame_share`, `weight`, `E_int(ens)`, `modal_n<N>.xyz` and `dft_export` selection. Measured by re-pooling one `--n 0 1 2 3 --seeds 5` sweep's own 480 candidates under both criteria: `E_int(min)` identical at every n to 0.00e+00 kcal/mol, `pool` 20/41/66 -> 41/114/137 at n = 1/2/3, basins flagged `!` 41 of 128 -> **0 of 293**, basins hit by >1 packing 71 -> 22, `found by` unchanged at 5/2/1, and `dft_export` 75 -> 200 structures (`--max-per-n` is the lever). Shared basins now sit 4-10x above the coincidence null instead of at it. `n_seeds_hit` falling is corroboration evidence being corrected downward rather than a regression. Not additive: a pre-0.11.0 `scored.json` has no `descriptor`, so `pool_by_n` and `dft_export` raise on it -- rescore, don't re-report |
| 0.10.0 | the modal basin -- the one the shell actually spent the most time in -- is a deliverable on the same footing the pooled minimum already was. `pool_by_n`'s `basins` entries gain identity (`run`, `seed`, `candidate_index`, `frame`, `min_gap_A`, `wall_energy_eV`) and recurrence (`n_visits`, `mean_dwell` from a new `report.basin_visits`, `n_seeds`, `contacts_split`); `pooled[n]` gains `modal`, the basin ranked by pooled `frame_share` (ties: `n_seeds_hit`, then energy), `None` for a docked chain. `report.txt` gains a Modal geometry at each n section and a `run:cand` locator, `+`/`*`/`!` marker column and `seeds`/`visits`/`dwell` columns in Basin occupancy; `modal_n<N>.xyz` is written beside `best_n<N>.xyz` for every n of a sweep (never for docking). `scored.log`'s candidate table gains `frames` / `visits` columns, `-` for a docked candidate. `dft_export.py` pools with `dedupe_groups` instead of `dedupe_energies` and gains `--occupancy-floor` (default 0.10): a basin at or above it is exported even outside the energy window, ordered ahead of window-only picks so `--max-per-n` never silently evicts one; `--occupancy-floor 1.1` reproduces the old window-only behaviour exactly. `manifest.json` entries gain `n_frames` / `frame_share` / `n_visits` / `n_seeds_hit` / `selected_by`, `null` / `"window"` for a docked export. Additive for `report.txt` and `manifest.json`; `basins` gains required keys, so a `sweep.json` re-rendered by `python -m report` needs the current `report.py` -- the standing rule for any `scored.json`-shape change |
| 0.9.0 | the defaults audited against what each generator is for since 0.8.0. **Docking**: `Docking.n_refine` is per parent, and the placements refined are chosen per parent among its *distinct* screened basins (`Docking.screen_dedupe_tol_eV`, 4 meV, new in the params block) rather than as a raw top-10 across every parent -- which could be ten copies of one basin, starving `n_parents` and capping `dft_export`'s window at ten candidates. Changes docking's numbers at identical params: at n >= 2 outright (more and different refined placements -- measured on pyrazine/chloroform, 30 refined and 19 distinct minima at n = 2 against 10 and 10, minimum -13.01 vs -13.00, found by 2/30 vs 1/10, 14 candidates exported at n = 2 vs 10), and at n = 1 by 0.35 meV (-6.6434 vs -6.6514 kcal/mol): the same basin, but refined from one representative placement rather than the best of six duplicates of it, so it converged to a marginally different point of the same minimum, under the 1 meV dedupe tolerance. `dock.json`'s params block loses `max_frames`, which docking never used. **Sweep**: `n_sweep.DEFAULT_SEEDS` is 5 (was a literal 3 in two places) and `Scoring.max_frames` is 30 (was 50) -- the same relaxations per n, spent on independent packings rather than on frames correlated within one trajectory. Changes what a default sweep runs, not how any given `Condition` is scored; a sweep's own params block already tells the two apart |
| 0.8.0 | two changes, landed together and both non-comparable. **Report shape**: the tables keep only the load-bearing columns -- `E_int(ens)`, `E(cluster)` and the distinct-minima `mean_contacts` / `dissolved_fraction` leave every table and `scored.log`'s Result block (they stay in the JSON), and the frame-weighted `occupancy_*` pair takes the `contacts` / `dissolved` columns. The ~150 lines of fixed prose every report carried move to README's "Reading report.txt". **Packing**: stratification is gone -- every solvent molecule is drawn independently again, `allocate_seeds` collapses to `n_seeds` everywhere and one at n = 0, and the Sampling convergence section goes with them. Changes the packing for **every n >= 2 run**, so sweeps either side are not comparable; `metadata.json` loses `pack_clustering` / `pack_directions` and the params block loses `pack_stratified`. Measured cost on one sweep: the n = 2 pooled minimum went -13.01 -> -11.40 kcal/mol, the both-nitrogens basin stratification used to buy -- which `docking.py` now finds by construction, which is why this is the intended trade |
| 0.7.3 | one rendering pipeline for both generators. The docking table gains a `wall` column (always `-`) and takes the sweep's column order; both Best geometry tables carry `frame`, `parent` and `E_wall/eV`, `-` where one does not apply. `report.dock_row_from_summary`, `format_dock_table`, `format_dock_best_geometry`, `_dock_increments`, `format_dock_report`, `write_dock_best_geometries` and `render_dock_dir` are gone; `pool_by_n` takes a docking `runs` list and carries `pack_mode` per row. No number moves |
| 0.7.2 | one candidate and one summary constructor for both generators (`ensemble.summarise`, `Candidate` for docking too). An MD candidate in `scored.json` gains `parent: null`; a docked candidate's `frame` is now its index among the refined placements *before* the dedupe rather than after. No number moves |
| 0.7.1 | `Scoring.stride`, `--stride` and the `stride` field of every summary are gone -- the `max_frames` cap always bit, so stride selected nothing. `ensemble.score_run` and `ensemble.dedupe` deleted (no callers, one caller). Readers index `pack_mode` / `n_refined` / `label` / `seed` directly instead of defaulting them, so a broken summary fails loudly. No number moves |
| 0.7.0 | an MD candidate in `scored.json` gains `n_frames` / `frames` -- how many scored frames quenched into that minimum, and their sampling dump indices, preserved through dedupe instead of discarded at it; each run's summary gains `scored_frame_spacing_fs`, `occupancy_mean_contacts`, `occupancy_dissolved_fraction`. `report.txt` gains a Basin occupancy section, fed by a `basins` list `pool_by_n` now attaches to each pooled n. The sweep table's `contacts` / `dissolved` columns are renamed `uniq cont` / `uniq diss`, because that is what they always measured -- the distinct minima a search turned up, not how the trajectory's time was spent. A docked candidate's occupancy fields are `null` (`pack_mode: "dock"` already says why -- see the `docking.py` section). Not additive: a pre-0.7.0 `scored.json` lacks `n_frames` on its candidates, so `pool_by_n` now raises on it rather than pooling silently without the counts -- rescore, don't re-report |
| 0.6.0 | the params block of `sweep.json` / `dock.json` loses `git_commit`, and `report.git_commit` is gone. It was blank on every cluster run (no `.git` in the copied tree, or no `git` in the batch environment), so it pinned nothing where it mattered. Subtractive: an older sweep still carries the field and re-renders unchanged, since the params block is rendered key-by-key with nothing reading `git_commit` by name |
| 0.5.0 | the params block of `sweep.json` / `dock.json` gains `ase_version`, `numpy_version` and the calculator's own library (`tblite_version`, or `mace_torch_version` / `torch_version`), from installed package metadata. Additive: nothing reads them, so older sweeps re-render unchanged |
| 0.4.0 | `scored.json` gains `pack_mode` (`"md"` or `"dock"`); every run directory gains `ref_solute.xyz` / `ref_solvent.xyz`, the relaxed reference geometries the run's `E_int` was measured against. `docking.py` (a second, constructive generator) and `dft_export.py` (candidate export for DFT) are new. Existing sweeps re-render unchanged (only the version line moves); `pack_mode` defaults to `"md"` when absent so nothing pre-0.4.0 breaks |
| 0.3.1 | `report.txt` gained a Best geometry at each n section and a `best` marker in the per-packing detail table; the sweep directory gained one `best_n<N>.xyz` per n. `report.py` only, so 0.3.0 sweeps re-render |
| 0.3.0 | the sweep table is per **n**, not per run: the candidates of every packing at one n are pooled and deduped across packings, and the reported number is the pooled minimum rather than a seed mean. `dE_int` is keyed by n alone; Seed spread becomes Search convergence; the old per-run rows are demoted to a Per-packing detail table. `report.py` only, so 0.2.0 sweeps re-render |
| 0.2.0 | stratified packing: the arrangement of the solvent now varies by design across the seeds at each n, and the seed budget is spread unevenly over n. Changes the packing for **every n >= 2 run**, so sweeps either side of it are not comparable. `report.txt` gained a `cover` column and `metadata.json` two fields |
| 0.1.1 | `report.txt` gained the `dE_int` column, so an 0.1.0 report has one fewer column and no increment. The docs' claim that `E_int(n)` plateaus was corrected in the same commit -- see `DESIGN.md`'s "It does not plateau, so read the increment" |
| 0.1.0 | first numbered version; `report.VERSION` added and recorded in the params block |
