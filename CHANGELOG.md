| 0.19.0 | **n >= 9 now runs, in both generators.** `descriptors_match` asks a bottleneck (minimax) assignment *feasibility* question -- does an assignment of one structure's solvent molecules to the other's exist whose max per-feature deviation is within tolerance -- which is not the sum-minimisation Hungarian solves and never needed it: thresholding the pairwise cost matrix and testing the resulting bipartite graph for a perfect matching (`report._has_perfect_matching`, Kuhn's augmenting-path algorithm, O(n_mol^3)) answers the identical predicate the old brute-force `itertools.permutations` search did, exactly rather than approximately -- verified on 2160 randomized pairs (matching, non-matching and near-threshold cases), zero disagreements. Measured head to head: 0.93 ms / 52.4 ms / 483.2 ms (permutation search, worst case, `n_mol` 6/8/9) against 8.8 / 8.4 / 15.4 microseconds (matching), and the matching test stays at 38.1 us at `n_mol` = 32 where a permutation search was never going to finish. `report.MAX_DESCRIPTOR_MOLECULES` therefore moves 8 -> 32 -- a sanity bound on descriptor size now, not an algorithmic limit, chosen to sit comfortably past a full first shell (~27 chloroform on pyrazine) rather than to fence off a cost cliff. **No number moves and no output shape changes at n <= 8** -- this is the same predicate, faster. Alongside it, `docking.run_docking` now rewrites `dock.json` / `dock_report.txt` / `best_n<N>.xyz` after every completed n instead of once at the end (all three writes are calculator-free and cheap against a generation of BFGS), so a chain that dies partway through leaves a readable report for every n it reached rather than stranding completed generations behind a crash with no top-level output -- which is what an n = 9 docking run used to do the moment it reached the dedupe, on a warning (`MONOLAYER_WARN_FRACTION` of a monolayer) that already said past-a-third-of-capacity is a bad idea for the chemistry, independent of any implementation limit.
